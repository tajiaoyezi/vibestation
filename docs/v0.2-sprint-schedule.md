### v2-D.2 协作流程（ADR-016 后）

1. **Spec 详化**：主 agent self-review · PR body 含 Arbiter approval trailer
2. **Phase 实施 dispatch**：主 agent 起草 Codex prompt（按 [`spike-tmp/dispatch/MVP-13-phase-A-codex-prompt.md`](../spike-tmp/dispatch/MVP-13-phase-A-codex-prompt.md) 模板 · 12 硬约束 + Phase 范围 + Acceptance + 交付要求）
3. **Codex 实施**：独立 worktree + git config Codex CLI · commit + push + 开 PR
4. **主 agent review**：12 硬约束 + Phase Acceptance + cargo test 复测 + H2 proof 验证
5. **Arbiter approval**：PR body trailer + 主 agent merge
6. **runtime 证据**：MVP / feature 类放 `docs/runtime-evidence/<task-id>/`（按 ADR-011 R1）
7. **admin override 例外**：admin direct push 走 ADR-016 §决策段豁免（commit body 必含 audit marker）

### R1 · GitHub Actions billing 状态未确认（session 21 暂停 · session 22-23 PR 都正常 merge · 可能已恢复）

- **影响**：若仍暂停 · PR-level CI 失效 · 主 agent 必须本地全过 gates · admin override 模式继续生效

### R2 · Codex 单一 agent 串行 · 工期紧

- **影响**：8 phase 总 9d · 若全靠 Codex 串行 · 工期 16d
- **缓解 option α**：主 agent 接 Phase B/C（Solid + xterm 类）· Codex 全力跑 backend
- **缓解 option β**：MVP-21 Phase A 与 MVP-13 Phase B/C/D 并行（spec 文件域隔离 · MVP-13 line 105 / MVP-21 line 127 已确认）
- **决策时机**：MVP-13 Phase A done 后（session 24+ · 主 agent + Arbiter 评估）

### R3 · BranchInfo / BranchKind 实际由 MVP-13 首次定义

- **背景**：spec §G.5 表写"复用 MVP-07 已生成 BranchInfo / BranchKind"是 stale assumption（实际仓库无此 binding · 主 agent + Codex 验证）
- **影响**：Phase A 实施时 Codex 必须新增（不是复用）· 12 binding（10 + 2）· spec §G.5 表表述错
- **Mitigation**：Phase A merge 后主 agent 开 follow-up PR 更新 spec §G.5 表（修正"由 MVP-13 首次定义"事实 · 不让 Codex 同 PR 改 · 避免 scope creep）
- **状态**：已识别 + 计划 follow-up（session 23 dispatch prompt review 阶段确认）

### R4 · 4 类 deferred GUI capture v0.2 GA 前必须 done

- **影响**：v0.2 GA release 前需要 Arbiter 跑 4 类 GUI capture（MVP-04 §I / MVP-05 Phase D / MVP-09 Phase D / MVP-10 §F.04）+ 主 agent 开 4 个 done PR
